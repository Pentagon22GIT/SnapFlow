# SnapFlow v1.1.1 Validation Plan

この文書は、v1.1.1で修正する連動リサイズ後のウィンドウ前後関係をmacOS実機で確認するためのチェックリストです。

## Automated checks

- [ ] `git diff --check`
- [ ] `zsh -n Scripts/*.sh`
- [ ] `swift test`
- [ ] `./Scripts/build-community.sh`
- [ ] Community版のコード署名検証
- [ ] `SnapFlowSourceRevision`がテスト対象コミットと一致
- [ ] `SnapFlowSourceDirty`が`false`

## Primary regression

- [ ] 左右に2分割したウィンドウの片方へ、Finderなど第三のウィンドウを重ねる
- [ ] スプリット境界を掴み、連動リサイズを確定する
- [ ] 実際に連動した両方のウィンドウが第三のウィンドウより前面に表示される
- [ ] 掴んでいたウィンドウがスプリット対象の中で最前面に残る
- [ ] キーボード入力先が連動先へ移らない

## Layout coverage

- [ ] 同じアプリの2ウィンドウで確認
- [ ] 異なるアプリの2ウィンドウで確認
- [ ] 3分割で、実際に連動した段だけが前面へ戻る
- [ ] 4分割で、実際に連動した全対象が前面へ戻る
- [ ] 境界へ未到達のウィンドウは前面化されない
- [ ] 侵害率超過または配置失敗で離脱したウィンドウは前面化されない

## Regression coverage

- [ ] 通常スナップの前面化と入力フォーカスに変化がない
- [ ] 連動リサイズ設定OFFでは従来どおり動作する
- [ ] 高速リサイズでも隙間や誤離脱が再発しない
- [ ] 仮想ボックスがMouseUp後に残らない
- [ ] 重いアプリでもドラッグ中の追従性能がv1.1.0から低下しない
- [ ] 連動中に対象ウィンドウを閉じてもクラッシュしない
- [ ] 別Spaceへの切り替えや次操作で古い前面化処理が実行されない

## Release gate

上記の主要回帰と通常スナップの確認が完了し、CIとCodeQLが成功するまでは`v1.1.1`タグを作成しません。
