# SnapFlow v1.2.2

v1.2.2は、Mission Controlやアプリ／Space切替で接続済みウィンドウを選んだ際、追加クリックなしでグループ全体を前面へ戻す修正版です。通常クリックの安定性、共有リサイズつまみの復旧負荷、安全な選択確認も改善しています。新しい権限、ネットワーク通信、外部依存関係は追加していません。

## ウィンドウ選択時のグループ前面化

通常クリックに加え、Mission Control、トラックパッド操作、Cmd+Tab、Space切替、同一アプリ内の別ウィンドウ選択を検知します。選択したウィンドウが現在も接続済みスプリットグループに所属している場合だけ、追従側を先に、選択ウィンドウを最後に前面へ上げます。

Accessibilityのmain／focused window通知は、アプリや切替方法によって届かない、遅れる、途中状態を示す場合があります。また、AX属性から取得した要素識別子は、通常のウィンドウ一覧側の要素識別子と一致しない場合があります。このためv1.2.2では、AX通知を選択確認開始の信号としてだけ使用し、最終的な選択対象には使用しません。

設定が有効でスナップ登録が2件以上あり、配置、ドラッグ、リサイズ、補助選択が進行していない場合だけ、frontmostアプリのPIDと最前面のWindow Server IDを100ms間隔で確認します。初回値と同じ状態では後続処理を開始しません。変化後は同じPIDとWindow IDが3回連続で安定するまで待ち、現在の可視ウィンドウ一覧に同じPIDとWindow IDが一件だけ存在する場合に選択を確定します。

待機確認ではウィンドウ画像、内容、キーボード入力、タイトル、フレーム、全AXウィンドウを取得しません。Window Server一覧からfrontmostアプリに対応する最初の通常ウィンドウIDだけを使用し、情報を保存または送信しません。

## 通常クリックと選択検知の分離

Mission Control上のmouse down／mouse upを通常クリックやドラッグ開始として扱い、自動選択確認を中止していた競合を修正しました。mouse downだけでは自動確認を止めず、実際のウィンドウ移動またはリサイズが確認された場合だけ保留処理を取り消します。

通常クリックとWindow Server選択確認は独立した世代番号と上限付きの保留処理を使用します。どちらの経路も現在の接続グラフを再解決し、前面化直前にPIDと選択Window IDを再確認します。古い世代の処理は結果へ作用できません。

## 再入防止と前面化後の確認

選択状態は同じPIDとWindow IDが3回連続で一致してから確定し、Mission Control中の一時的な`nil`や前後順変化は最大約1秒の範囲で待機します。確定後に選択が変わった場合は古い要求を破棄します。

前面化は現在も共有境界でつながっているグループだけが対象です。追従側を既存順序で先に上げ、選択対象を最後に上げます。結果を確認し、まだグループが前面へそろっていない場合だけ一度再試行します。すでに前面の場合はAXRaiseを行いません。

SnapFlow自身のAXRaiseで通知やWindow Server順が変化しても、同じ選択と前面状態なら追加Raiseへ進みません。設定画面、配置、ドラッグ、連動リサイズ、確定処理の開始時には古い選択要求を世代番号で無効化します。

## 待機中と復旧時の負荷

100msの選択確認は`CGWindowListCopyWindowInfo`から、frontmostアプリのPID、layer 0、alphaが0より大きい最初のWindow IDだけを読みます。全レコードのフレーム変換やタイトル取得、AXウィンドウ列挙は行いません。変化が安定した場合だけ、接続判定に必要な現在のウィンドウ一覧を取得します。

1秒ごとの復旧タイマーは安全装置として維持しますが、通常ウィンドウのID、PID、フレーム、相対Z順が変化した場合だけ全ウィンドウとハンドルを再構築します。メニューやツールチップなどlayer 0以外の一時UIは復旧比較から除外します。

## 安全性と互換性

- 前面化直前にfrontmost PIDと選択Window IDを再確認します。
- 選択Window IDは可視ウィンドウ側のPIDと完全一致した場合だけ使用します。
- 接続解除済み、別Space、不可視、別PIDのウィンドウは前面化しません。
- 前面化は最大二回のAXRaise試行で停止します。
- 設定OFF、SnapFlow UI表示中、配置、ドラッグ、リサイズ、確定中は自動前面化を開始しません。
- 一時的なZ順や通知から恒久的な接続状態を変更しません。
- observerは現在のfrontmostアプリ一つだけへ登録し、通知未対応時もWindow Server確認で補完します。
- 新しい権限、外部Package、ネットワーク処理、Helper、XPC、Daemon、永続ログを追加していません。
- 既存のv1.2.0／v1.2.1設定を引き継ぎます。
