# Threat Model

最終更新日: 2026-08-05

## 目的

SnapFlowはAccessibilityと任意の画面収録という強いmacOS権限を使用します。この文書は、公式v1.1.0が保護する対象、想定する攻撃者、信頼境界、残るリスクを明示します。

## 保護対象

- 利用者がSnapFlowへ与えたAccessibility許可
- 利用者が任意で与えた画面収録許可
- 画面上の候補画像とウィンドウタイトル
- ウィンドウの位置、サイズ、フルスクリーン状態
- 公式Releaseの真正性と完全性
- 公式コード署名秘密鍵
- GitHubリポジトリとRelease履歴
- 利用者が期待する手動更新経路

## 想定する攻撃

### 公式版へのなりすまし

攻撃者が同じ表示名、アイコン、Bundle IDを持つアプリを作り、過去に与えられた権限を利用しようとする攻撃です。

対策:

- 公式版のDRをBundle IDだけでなく自己署名証明書SHA-1へ固定
- 秘密鍵をGitHubや配布物へ含めない
- Community版を別Bundle IDへ分離
- 旧identifier-only DRのTCC許可を公開前にリセット
- Release manifestと署名確認手順を公開

### Releaseの差し替え・改ざん

ダウンロード中、ミラー、侵害されたアカウントなどで公式ZIPが別ファイルへ置換される攻撃です。

対策:

- Gitの署名済みタグ
- GitHubのVerified表示
- ZIPのSHA-256
- アプリのコード署名
- Certificate SHA-1とsource commitを含むmanifest
- 公開後の再ダウンロード検証
- 同一バージョン資産を差し替えない運用

### 画面情報の意図しない取得

配置に不要な場面でも画面収録APIを使用し、機密情報がメモリやディスクへ残る危険です。

対策:

- プレビュー初期OFF
- 連動リサイズの仮想ボックスは画面画像を取得せず、AppKitのぼかしとアプリアイコンだけで構成
- 連動リサイズ開始時のWindowServer列挙はAX対象とのID照合に一度だけ使用し、照合後の連続取得は確認済みの単一ウィンドウIDと外枠情報に限定
- 明示的に有効化した場合だけ画像APIを呼ぶ
- 遅延取得と表示範囲付近だけの取得
- メモリキャッシュのみ
- 配置アシスト終了時にキャッシュを破棄
- 保存・通信機能を持たない

### キー入力の過剰取得

Accessibility許可を利用し、アプリが不要なキー入力を常時受け取る危険です。

対策:

- 通常のグローバル監視はマウスイベントだけ
- グローバルkeyDown監視は配置アシスト表示中だけ
- Esc以外を処理しない
- 配置アシスト終了時に監視を解除
- ショートカット入力は自アプリの設定画面だけでローカル監視

### 悪意あるContribution・依存関係

Pull Requestや外部Actionから、情報送信や秘密鍵取得処理が混入する攻撃です。

対策:

- mainへの直接変更を避ける
- Pull Request差分確認
- macOS CIとCodeQL
- 外部Actionを完全なコミットSHAへ固定
- DependabotによるAction更新
- Workflowを最小権限に設定
- GitHub Actionsへ公式署名鍵を置かない
- Swiftの外部Package依存をv1.1.0では持たない

### 更新経路の乗っ取り

アプリが攻撃者の更新ファイルを自動ダウンロード・実行する攻撃です。

対策:

- v1.1.0は自動更新を実装しない
- 「更新を確認…」は固定HTTPS URLをブラウザで開くだけ
- ダウンロード、展開、置換、実行をアプリ内で行わない
- 更新は利用者がReleaseと署名を確認して手動実施

## 信頼境界

### MaintainerのMac

公式署名秘密鍵を保持する最重要境界です。端末侵害、Keychain侵害、バックアップ漏えいが発生すると、攻撃者が公式署名条件を満たせます。

### GitHub

ソース、タグ、Release、Issue、Security Advisoryを保持します。GitHubアカウント侵害だけでは公式コード署名を生成できませんが、利用者を偽ファイルへ誘導できます。

### 利用者のMac

最終的な権限付与主体です。macOSのTCC、コード署名検証、利用者による入手元確認に依存します。

### Community版

公式信頼境界の外です。利用者が自身でコードを確認し、自身の判断で権限を付与します。

## 対象外または防げないもの

- root権限や利用者セッションを完全に奪取済みの攻撃者
- macOS、AppKit、Accessibility、CoreGraphics自体の未知の脆弱性
- Maintainerの公式秘密鍵が盗まれた後の、Appleによる証明書失効
- 利用者が署名警告を無視して第三者配布物へ権限を与えること
- ForkがSnapFlowの名称を使用すること自体
- すべてのウィンドウアプリ固有制約に対する完全互換

## 残余リスク

| リスク | 影響 | 現在の扱い |
|---|---|---|
| 自己署名のためGatekeeperが開発者を認証しない | 利用者が手動判断を誤る | 署名・SHA確認手順を提示 |
| 秘密鍵を失う | 同一署名で更新不能 | 暗号化オフラインバックアップ |
| 秘密鍵が漏れる | 偽公式版を作成可能 | 鍵分離、非クラウド保管、移行手順 |
| Accessibilityの強い権限 | アプリ侵害時の影響が大きい | 機能最小化、外部入力・通信なし |
| プレビュー画像がメモリに存在 | ローカルメモリ解析で閲覧可能 | 初期OFF、短期間保持、保存なし |
| AXウィンドウ同定の誤り | 誤ウィンドウ移動 | PID、AX identity、CG geometry、再確認 |
| WindowServer IDの照合誤り | 別ウィンドウへガイドが追従 | PID、タイトル、開始時のAX/CG geometry、前面順で一度だけ照合し、確定処理はAX identityを継続使用 |
| 複数ウィンドウ再配置の途中失敗 | レイアウトの部分適用 | 配置前スナップショット、全対象の成否確認、キャンセルを含むトランザクション単位のロールバックとUndo |
| アプリ固有の最小サイズ推定が不正確 | 過度な重なりまたは不要な再配置 | 要求サイズと実サイズからウィンドウ単位で観測し、固定絶対値を使わず、許容率とヒステリシスを適用 |
| GitHubアカウント侵害 | 偽Releaseへの誘導 | 2FA、署名タグ、別管理のコード署名鍵 |

## 再評価が必要な変更

次を追加する場合は、実装前にこの脅威モデルとSECURITY_AUDITを更新します。

- 自動更新
- ネットワーククライアント
- クラッシュレポートやテレメトリー
- 外部Swift Package
- Helper、XPC Service、LaunchDaemon
- ファイル保存または設定同期
- Apple Events
- クリップボードアクセス
- 公式署名鍵のGitHub Actions利用
