# Threat Model

最終更新日: 2026-08-07

## 目的

SnapFlowはAccessibilityと任意の画面収録という強いmacOS権限を使用します。この文書は、公式v1.2.3が保護する対象、想定する攻撃者、信頼境界、残るリスクを明示します。

## 保護対象

- 利用者がSnapFlowへ与えたAccessibility許可
- 利用者が任意で与えた画面収録許可
- 画面上の候補画像とウィンドウタイトル
- ウィンドウの位置、サイズ、フルスクリーン状態
- 公式Releaseの真正性と完全性
- 公式コード署名秘密鍵
- GitHubリポジトリとRelease履歴
- 利用者が期待する手動更新経路

## 想定する攻撃

### 公式版へのなりすまし

攻撃者が同じ表示名、アイコン、Bundle IDを持つアプリを作り、過去に与えられた権限を利用しようとする攻撃です。

対策:

- 公式版のDRをBundle IDだけでなく自己署名証明書SHA-1へ固定
- 秘密鍵をGitHubや配布物へ含めない
- Community版を別Bundle IDへ分離
- 旧identifier-only DRのTCC許可を公開前にリセット
- Release manifestと署名確認手順を公開

### Releaseの差し替え・改ざん

ダウンロード中、ミラー、侵害されたアカウントなどで公式ZIPが別ファイルへ置換される攻撃です。

対策:

- Gitの署名済みタグ
- GitHubのVerified表示
- ZIPのSHA-256
- アプリのコード署名
- Certificate SHA-1とsource commitを含むmanifest
- 公開後の再ダウンロード検証
- 同一バージョン資産を差し替えない運用

### 画面情報の意図しない取得

配置に不要な場面でも画面収録APIを使用し、機密情報がメモリやディスクへ残る危険です。

対策:

- プレビュー初期OFF
- 連動リサイズの仮想ボックスは画面画像を取得せず、AppKitのぼかしとアプリアイコンだけで構成
- つまみの仮想表示は画面画像を使わず、AppKitのぼかし、ガイド、アプリアイコンだけで構成
- 明示的に有効化した場合だけ画像APIを呼ぶ
- 遅延取得と表示範囲付近だけの取得
- メモリキャッシュのみ
- 配置アシスト終了時にキャッシュを破棄
- 保存・通信機能を持たない

### キー入力の過剰取得

Accessibility許可を利用し、アプリが不要なキー入力を常時受け取る危険です。

対策:

- 通常のグローバル監視はマウスイベントだけ
- グローバルkeyDown監視は配置アシスト表示中またはつまみ操作中だけ
- Esc以外を処理しない
- 配置アシスト終了時に監視を解除
- ショートカット入力は自アプリの設定画面だけでローカル監視

### 悪意あるContribution・依存関係

Pull Requestや外部Actionから、情報送信や秘密鍵取得処理が混入する攻撃です。

対策:

- mainへの直接変更を避ける
- Pull Request差分確認
- macOS CIとCodeQL
- 外部Actionを完全なコミットSHAへ固定
- DependabotによるAction更新
- Workflowを最小権限に設定
- GitHub Actionsへ公式署名鍵を置かない
- Swiftの外部Package依存をv1.2.3では持たない

### 更新経路の乗っ取り

アプリが攻撃者の更新ファイルを自動ダウンロード・実行する攻撃です。

対策:

- v1.2.3は自動更新を実装しない
- 「更新を確認…」は固定HTTPS URLをブラウザで開くだけ
- ダウンロード、展開、置換、実行をアプリ内で行わない
- 更新は利用者がReleaseと署名を確認して手動実施

## 信頼境界

### MaintainerのMac

公式署名秘密鍵を保持する最重要境界です。端末侵害、Keychain侵害、バックアップ漏えいが発生すると、攻撃者が公式署名条件を満たせます。

### GitHub

ソース、タグ、Release、Issue、Security Advisoryを保持します。GitHubアカウント侵害だけでは公式コード署名を生成できませんが、利用者を偽ファイルへ誘導できます。

### 利用者のMac

最終的な権限付与主体です。macOSのTCC、コード署名検証、利用者による入手元確認に依存します。

### Community版

公式信頼境界の外です。利用者が自身でコードを確認し、自身の判断で権限を付与します。

## 対象外または防げないもの

- root権限や利用者セッションを完全に奪取済みの攻撃者
- macOS、AppKit、Accessibility、CoreGraphics自体の未知の脆弱性
- Maintainerの公式秘密鍵が盗まれた後の、Appleによる証明書失効
- 利用者が署名警告を無視して第三者配布物へ権限を与えること
- ForkがSnapFlowの名称を使用すること自体
- すべてのウィンドウアプリ固有制約に対する完全互換

## 残余リスク

| リスク | 影響 | 現在の扱い |
|---|---|---|
| 自己署名のためGatekeeperが開発者を認証しない | 利用者が手動判断を誤る | 署名・SHA確認手順を提示 |
| 秘密鍵を失う | 同一署名で更新不能 | 暗号化オフラインバックアップ |
| 秘密鍵が漏れる | 偽公式版を作成可能 | 鍵分離、非クラウド保管、移行手順 |
| Accessibilityの強い権限 | アプリ侵害時の影響が大きい | 機能最小化、外部入力・通信なし |
| プレビュー画像がメモリに存在 | ローカルメモリ解析で閲覧可能 | 初期OFF、短期間保持、保存なし |
| AXウィンドウ同定の誤り | 誤ウィンドウ移動 | PID、AX identity、CG geometry、再確認 |
| WindowServer IDの照合誤り | 別ウィンドウへガイドが追従、参加ウィンドウを遮蔽物と誤認 | IDをPIDと現在フレームで再検証し、一対一の代替候補を確定できない場合は入力パネルを作らず、確定処理はAX identityを継続使用 |
| 複数ウィンドウ再配置の途中失敗 | レイアウトの部分適用 | 配置前スナップショット、全対象の成否確認、キャンセルを含むトランザクション単位のロールバックとUndo |
| 連続したAXリサイズ要求 | 対象アプリとSnapFlowの応答低下 | 一つの直列処理、最新値への置換、世代によるキャンセル、操作終了後の確定検証 |
| つまみパネルによる入力妨害 | 他アプリを操作できない | 共有境界の一部でも外部ウィンドウが覆えばdescriptor全体を除去し、初回または参加者照合が不完全な間は入力を無効化し、設定画面、Space変更、無効化、関係消失時に破棄 |
| 遮蔽表示と操作開始の競合 | 間にある外部ウィンドウを越えて参加者だけが前面化 | MouseDown直前にWindow Server情報と現在のbase descriptorを再検証し、遮蔽・照合失敗時はAXRaise前に中止 |
| 通常クリックと配置確定の競合 | 未確定配置の中断または意図しないロールバック | 補助表示を閉じる軽量経路と全操作キャンセルを分離し、macOSのZ順確定待ち後に現在の接続だけを再解決 |
| クリック前面化要求の蓄積 | AX要求の集中、CPU・メモリ増加、古い結果の適用 | 保留を最新一件の`DispatchWorkItem`へ限定し、世代番号で取消、前面化を最大二回で停止 |
| Mission Control選択と通常クリックの競合 | 自動選択処理の取消、追加クリックまでグループが復帰しない | Window Server選択確認を通常クリックとは別の世代と最大一件の保留処理で管理し、実際の移動・リサイズ開始時だけ両方を無効化 |
| AX main／focused要素の取り違え | 古いウィンドウまたは別グループの前面化 | AX通知は開始信号だけに使用し、同じPIDとWindow Server IDが連続安定して現在の可視ウィンドウへ完全一致した場合だけ選択確定 |
| Window Server選択IDの再利用・変化 | 別PID、別Space、古いウィンドウへのAXRaise | 前面化直前にfrontmost PIDとWindow IDを再確認し、現在の共有境界グラフに存在しない対象は中止 |
| 選択確認の定常負荷 | 不要状態でのWakeup、操作待機中のCPU使用率増加 | 長寿命な有効条件を満たす間だけ10Hz Timerを生成し、変化時だけ全ウィンドウを照合。OFF・登録不足ではTimerを停止し、全レコードのフレーム・タイトル変換を行わない |
| 監視Timerの再開漏れ | Mission Control等の選択を検出できず追加クリックが必要 | 設定・登録・起動状態から即時再評価し、1秒Recoveryでも状態を再確認。再開時は最初の値をbaselineだけに使用 |
| 古い遮蔽・前面化タイマー | 新しい状態へ古いつまみを再表示 | 表示世代の一致確認、確認済み表示の保持、未確認中の入力停止、最新要求だけを有効化 |
| Window Server障害時の遮蔽再試行 | 不要な定常CPU負荷 | 短時間再試行を6回で停止し、その後は既存の1秒リカバリだけを使用 |
| 一時的な重なりによる恒久解除 | 利用者の意図しない連動関係の消失 | 遮蔽は表示と入力だけへ反映し、恒久接続は明示的な移動・リサイズ判定だけから変更 |
| アプリ固有の最小サイズ推定が不正確 | 過度な重なりまたは不要な再配置 | 要求サイズと実サイズからウィンドウ単位で観測し、固定絶対値を使わず、許容率とヒステリシスを適用 |
| 子設定が親トグルを迂回 | OFFにした連動リサイズ処理が一部だけ動作 | 実効状態を親と子の論理積として一箇所で算出し、UIと実行経路の両方で無効化 |
| GitHubアカウント侵害 | 偽Releaseへの誘導 | 2FA、署名タグ、別管理のコード署名鍵 |

## 再評価が必要な変更

次を追加する場合は、実装前にこの脅威モデルとSECURITY_AUDITを更新します。

- 自動更新
- ネットワーククライアント
- クラッシュレポートやテレメトリー
- 外部Swift Package
- Helper、XPC Service、LaunchDaemon
- ファイル保存または設定同期
- Apple Events
- クリップボードアクセス
- 公式署名鍵のGitHub Actions利用
