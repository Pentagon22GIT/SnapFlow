# SnapFlow v1.2.3

v1.2.3は、v1.2.2で追加したMission Control、アプリ／Space切替、同一アプリ内選択の安定性を維持しながら、監視結果を利用しない状態の不要なTimer Wakeupを削減する常駐効率改善です。

## 必要な期間だけ選択監視

100msのWindow Server選択確認は、次をすべて満たす間だけTimerを生成します。

- SnapControllerが起動中
- SnapFlowが有効
- 連動リサイズが有効
- 接続グループ前面化が有効
- スナップ登録が2件以上

設定OFF、SnapFlow無効、登録0〜1件ではTimer自体を停止します。再び条件を満たすと内部状態から即時再開し、最初の選択値はbaseline保存だけに使用します。

## 復旧経路は維持

既存の1秒Recovery Timerは、SnapFlow無効中を含めv1.2.2と同じ寿命・周期で維持します。設定や登録状態の遷移で10Hz監視の再評価が漏れた場合にも、最大約1秒で再確認するSafety Netとして機能します。

今回ライフサイクル化するのは10Hz選択Timerだけです。Recovery Timerの停止条件、生成方法、周期、RunLoop登録方法は変更していません。

## 維持した安全性

- Window Server選択確認は接続グループが成立し得る間、従来どおり10Hzを維持します。
- AX通知だけに依存する方式へ戻していません。
- PIDとWindow IDの変化検出、3回連続安定確認、現在の可視ウィンドウへの完全一致を維持します。
- 前面化直前に選択と現在の接続グラフを再確認します。
- 古い世代の要求を破棄し、前面化試行を最大二回に制限します。
- Timer停止時はbaselineと保留中の自動前面化を破棄します。

## 採用しなかった変更

5Hz化、idle時の適応周波数、AX通知が来た場合だけの監視開始、接続グラフの推測キャッシュは採用していません。これらは省電力効果よりMission Controlや同一アプリ内選択の回帰リスクが大きいためです。

## 互換性

- 新しい権限、外部Package、ネットワーク通信、画面取得、永続ログは追加していません。
- v1.2.2までの設定を引き継ぎます。
- Minimum macOS versionは13.0のままです。
