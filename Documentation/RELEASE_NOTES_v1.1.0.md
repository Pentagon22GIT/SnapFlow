# SnapFlow v1.1.0

SnapFlow v1.1.0では、固定された50%の配置から、現在のウィンドウ境界を基準にした動的スプリットへ内部設計を更新しました。

## 主な変更

- スナップ後に共有辺をドラッグすると、三分割と四分割を構成する縦線または横線を単位として連動します。
- 上下または左右の境界がずれている場合は、操作中の辺が別の段の境界へ到達した時点で同じ線へ合流します。
- 操作中のウィンドウを優先し、連動先はMouseUpまで実際にはリサイズしません。
- 連動先は操作中だけ、ぼかし、青いガイド、中央のアプリアイコンを組み合わせた仮想ボックスで示します。
- Discordなど、最初から半分へ収まらないウィンドウでは、実際の端へ到達するまで連動を待機します。
- 連動先が受け入れられなかった追加のずれが設定値を超えた場合、その共有辺を解除します。
- 連動先が極端に小さくなる場合は仮想表示とリサイズ要求を停止し、全画面方向の操作を妨げません。
- 既存のウィンドウが画面の60%を使用している場合、反対側への新しいスナップは残り40%を使用します。
- 残り領域が対象ウィンドウの制約基準に対して不足しすぎる場合は、配置後の境界が到達した縦線または横線の段を一段階再分割します。
- 再分割に参加する全ウィンドウが許容度を満たした場合だけ確定し、失敗時は一括で元へ戻します。
- 固定ptや画面全体の割合ではなく、ウィンドウごとに観測した制約サイズから侵害率を計算します。
- 「状態をリセット」ではショートカットや各種設定を削除しなくなりました。
- ドラッグ中のAccessibility照会とガイド再計算を抑え、ブラー枠を遅延アニメーションではなく最新位置へ直接追従させました。
- 共有辺でMouseDownした時点に限って追従関係と非表示ブラーを準備し、最初の追従開始を高速化しました。
- 三分割以上の仮想ボックスを一つの共有パネルで描画し、ブラー、ガイド、アイコンの前後関係を固定しました。
- 連動中の複数ボックスを一括更新し、操作中ウィンドウの外枠はWindowServerから最大60Hzで取得します。同じフレームは再描画しません。
- 連動リサイズは初期状態で有効ですが、設定から無効化して通常のスナップだけを使用できます。
- MouseUp後に最終フレームが安定してから一本の境界を確定し、連動先を厳密に再確認して一括確定します。
- 配置途中は対象を離脱検査から一時的に分離しますが、完成状態のスナップ判定許容値は変更していません。
- MouseUpイベントの取りこぼし時も通常と同じ確定処理を継続し、確定途中のキャンセルではSnapFlowが変更した連動先だけを操作前の位置へ戻します。
- 連動先の再補正後に画面外周を維持できない場合は、その配置を正式な共有辺として記録しません。

## 権限とプライバシー

必要な権限に変更はありません。連動リサイズの確定にはAccessibility権限を使用します。操作中のWindowServer情報はウィンドウIDと外枠だけを使用し、画像は取得しません。仮想ボックスは画面キャプチャを使用しないため、この機能だけを利用する場合に画面収録権限は不要です。

## 既知の制約

macOSは他アプリの正確な最小・最大ウィンドウサイズを共通APIとして提供しません。SnapFlowは、実際に要求したサイズと受け入れられたフレームからウィンドウ単位の制約ヒントを更新します。まだ限界を観測できていない場合は、そのウィンドウの操作前サイズと標準区画サイズの小さい方を暫定基準にします。アプリ独自の制約変更によって、共有辺に一時的な重なりや隙間が残る場合があります。

四隅への新規スナップで横・縦の両軸が同時に許容度を超える場合、対角ウィンドウを二軸同時に変更する不安定なトランザクションを避けるため、その配置を中止して元の状態へ戻します。

複数ディスプレイ、異なる拡大率、Discord、システム設定、Finder、主要ブラウザ、三分割、四分割での実機確認を推奨します。

公式版は、Git管理され、未コミット・未追跡の変更がないソースからのみビルドできます。アプリ内の`SnapFlowSourceRevision`と`SnapFlowSourceDirty`によってビルド元を検証します。
