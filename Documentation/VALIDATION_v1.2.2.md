# SnapFlow v1.2.2 Validation Record

検証基準日: 2026-08-07

## 自動・静的確認

```zsh
git branch --show-current
git status --short
git diff --check
zsh -n Scripts/*.sh
swift test
./Scripts/build-community.sh
```

- [ ] Window Server選択状態の初回観測は基準保存だけで、前面化を開始しない
- [ ] PIDまたはWindow IDが変化した場合だけ新しい選択として検出する
- [ ] Mission Control中に一時的に選択が取得不能になっても、復帰後の値を新しい選択として検出する
- [ ] 同じPIDとWindow IDが3回連続で一致するまでグループ判定を開始しない
- [ ] 100ms確認では画像、タイトル、フレーム、全AXウィンドウを取得しない
- [ ] layer 0、alphaが0より大きい、frontmost PIDの最初のWindow IDだけを候補にする
- [ ] 選択確定後は同じPIDと`CGWindowID`を持つ現在の可視ウィンドウへ完全一致させる
- [ ] 前面化直前にfrontmost PIDとWindow IDを再確認する
- [ ] 通常クリックとWindow Server選択確認が別々の世代番号と最大一件の`DispatchWorkItem`を持つ
- [ ] 実際のドラッグまたはリサイズ開始時に両方の保留経路を無効化する
- [ ] AX通知は直接AXRaiseを呼ばず、Window Server選択確認の開始信号としてだけ使用する
- [ ] 前面化は現在の共有境界グラフだけを対象とし、追従側を先、選択対象を最後に上げる
- [ ] 前面化試行が最大二回で停止する
- [ ] すでにグループ全体が前面の場合はAXRaiseを行わない
- [ ] 設定OFF、SnapFlow UI表示中、配置、ドラッグ、リサイズ、確定中は自動前面化を開始しない
- [ ] 復旧タイマーは通常ウィンドウ構成の変化なしに全AXウィンドウを再列挙しない
- [ ] 新しい外部Package、ネットワーク処理、画面画像取得、権限、永続保存を追加していない

## macOS実機で必須の確認

### 基本選択

- [ ] 左右、上下、三分割、四分割の各構成で、各参加ウィンドウを通常クリックするとグループが前面化する
- [ ] Mission Controlから別アプリの参加ウィンドウを選択し、追加クリックなしで接続相手も前面へそろう
- [ ] Mission Controlから同一アプリの別ウィンドウを選択し、そのウィンドウのグループだけが前面化する
- [ ] トラックパッド操作で別Spaceの参加ウィンドウを選択し、Space確定後に接続相手も前面へそろう
- [ ] Cmd+Tabで参加ウィンドウを持つアプリへ移り、最前面の参加ウィンドウに対応するグループだけが前面化する
- [ ] Finder、Chrome、Discordなど複数のアプリで同じ結果になる
- [ ] 選択ウィンドウがグループ内で最後まで最前面に残る
- [ ] 接続されていないウィンドウを選択しても、別の接続グループが前面化しない

### 競合と点滅

- [ ] Mission Control終了後に追加クリックせず、おおむね200〜400ms以内に相方が前面化する
- [ ] Mission Control終了直後に別ウィンドウを選択し直しても、古いグループが後から前面へ出ない
- [ ] アプリ切替とSpace切替が連続しても、最後に確定した選択だけが結果へ反映される
- [ ] 前面化直後に同じアプリの別ウィンドウを選択しても、新しい選択が失われない
- [ ] すでに前面のグループを連続して選択しても、点滅、再配置、継続的なAXRaiseがない
- [ ] Mission Control上のmouse down／mouse upだけでドラッグ状態へ移行しない
- [ ] 通常クリックが自動選択確認を破壊せず、自動選択確認も通常クリックの確実なフォールバックを破壊しない
- [ ] ハンドルが選択開始時と前面化完了時に何度も消滅・再生成されない
- [ ] 設定画面を開閉した後、対象アプリへ戻ると監視とハンドルが正常に復帰する

### 負荷と復旧

- [ ] 操作せず10分待機し、CPU使用率とメモリ使用量が継続的に増加しない
- [ ] 変化のない状態で毎秒すべてのアプリへAX照会している兆候がない
- [ ] 変化のない100ms確認で全AXウィンドウ列挙、タイトル取得、フレーム変換、ハンドル再構築が発生しない
- [ ] Window Server一覧取得が10Hzを超えて増え続けない
- [ ] メニュー、ツールチップ、通知バナーの表示だけで誤前面化や継続的な再構築が起きない
- [ ] YouTube、Discord、Chromeなど重いウィンドウでも選択要求が蓄積しない
- [ ] ウィンドウの移動、リサイズ、終了、最小化、Z順変更後は1秒以内または通知直後にハンドルが正しい状態へ戻る

### 回帰と安全性

- [ ] 設定をOFFにすると通常クリック、Mission Control、アプリ／Space切替のいずれでも接続相手を前面化しない
- [ ] 連動リサイズの軽量、標準、すべて表示モードで確定とEsc取消が正常に動く
- [ ] MouseUp後の最終補正、Undo、補助選択、最小サイズ判定が後退していない
- [ ] 実際にウィンドウをドラッグすると、古い自動前面化要求が後から実行されない
- [ ] 共有境界が外部ウィンドウで覆われた場合、透明な入力領域が残らない
- [ ] 接続解除済み、別ディスプレイ、別Space、不可視、別PIDのウィンドウを誤って前面化しない
- [ ] 同じアプリの非グループウィンドウを選んでも、その背後にあるグループを誤って前面化しない
- [ ] Accessibility以外の新しい権限を要求しない
- [ ] 画面収録OFFでも、候補画像以外の前面化機能が正常に動く
