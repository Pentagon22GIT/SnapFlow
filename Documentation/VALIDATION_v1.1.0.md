# SnapFlow v1.1.0 Validation Plan

この文書は、v1.1.0の機能ブランチをmacOS実機で検証するためのチェックリストです。既存の`Documentation/VALIDATION.md`に記録されたv1.0.0の完了実績を上書きしません。

## 安全なブランチ運用

実際のGitリポジトリで、最新の`main`から機能ブランチを作成します。

```zsh
git switch main
git pull --ff-only origin main
git status --short
git switch -c feature/dynamic-split-resize
```

置き換え用ファイルを反映した後、意図しない生成物や秘密情報が含まれていないことを確認します。

```zsh
git status --short
git diff --check
git diff --stat
git diff
git ls-files --others --exclude-standard
find . -type f \( -iname '*.p12' -o -iname '*.pfx' -o -iname '*.pem' -o -iname '*.key' \) -print
```

## ビルド前検証

完全なXcodeを選択したmacOS上で実行します。

```zsh
xcode-select -p
zsh -n Scripts/*.sh
swift test
./Scripts/build-community.sh
codesign --verify --strict --verbose=4 "build/community/SnapFlow Community.app"
open "build/community/SnapFlow Community.app"
```

Community版は公式版とBundle IDおよびAccessibility権限を共有しません。実機テストでは`SnapFlow Community`へ別途Accessibility権限を許可します。候補画像を試す場合だけ画面収録権限を許可します。

## 状態リセット

- ショートカットを複数登録してから「状態をリセット」を実行する
- ショートカット、重なり許容度、ドラッグ判定、候補画像、連動リサイズ、ログイン項目の設定が保持される
- 現在の固定状態、スプリット関係、Undo履歴、復元フレーム、ガイド、候補画面が消える
- リセット後に通常のスナップを新規に開始できる

## 動的スナップ

- 左側を約60%へ広げた後、右端スナップのガイドと候補が残り約40%になる
- 上段60%・下段50%のように境界が揃わない状態で、全高の反対側スナップが最も内側の安全境界を使う
- 新しいウィンドウが残り領域より大きい場合、通常スナップは中止せず、外周を保ったまま重なりを許容する
- 極端に小さい候補領域でも、候補UIが画面外へはみ出したり操作不能なパネルを残したりしない
- 残り領域の不足が対象ウィンドウの許容度を超える場合、配置後の境界が到達した縦線または横線の段が再分割される
- 再分割先の一つが許容度を超える場合、新しいウィンドウと既存側の全対象が元へ戻る
- 四隅で横・縦の両軸が同時に許容度を超える場合、対角ウィンドウを巻き込まず全対象が元へ戻る
- 再分割をUndoすると、同時に変更された全ウィンドウが一括で戻る

## 連動リサイズ

- 二分割で共有辺を動かすと、操作中は利用者が掴んだウィンドウだけが実際に動く
- 連動先がぼかし、青い枠、中央のアプリアイコンへ切り替わる
- マウスの停止では確定せず、左ボタンを離した瞬間だけ連動先をリサイズする
- 実ウィンドウのフレーム確認後、仮想ボックスがフェードせず消える
- リサイズ後もスナップ前の復元サイズが書き換わらない
- 四分割で縦境界が揃っている場合、上段から動かしても下段を含む一本の縦線として連動する
- 四分割で横境界が揃っている場合、左列から動かしても右列を含む一本の横線として連動する
- 上下の縦境界がずれている場合、操作中の縦辺が別の段の境界へ到達するまではその段を動かさず、到達後に同じ線として連動する
- 左右の横境界がずれている場合も、別の列の境界へ到達した時点から同じ線として連動する
- 全高または全幅ウィンドウを含む三分割では、分割できないウィンドウの途中だけが動かない
- 通常のタイトルバードラッグが連動判定によって重くならない
- 同じスナップ候補内でガイドアニメーションが繰り返し再起動しない
- ブラー枠が0.10秒遅れて追う動きにならず、最新フレームへ直接追従する
- 共有辺を高速に掴んで動かし始めても、初回だけブラー枠が大きく遅れない
- 三分割と四分割で複数の仮想ボックスが同時に表示されても、青枠とアイコンが別対象のブラーの下へ隠れない
- 境界へ途中から合流する仮想ボックスが表示されても、既存ボックスの前後関係や濃さが変化しない
- 許容侵害率を往復して対象が一時停止・再参加しても、古いブラーや青枠が残らない
- 共有辺を高速に動かしてMouseUpしても、操作ウィンドウの最終位置まで連動先が伸び切る
- MouseUp直後の配置中に固定状態が解除されず、次のリサイズでも同じ境界グループとして認識される
- 共有境界が1ptを超えてずれた場合は再補正され、全対象の確定後にブラーが即時消える
- グローバルMouseUpを取りこぼした状態を再現しても、1秒以内に通常の確定経路へ入り、連動先と固定状態が失われない
- MouseUp直後の連動先確定中に別ウィンドウをクリックした場合、未確定の連動先だけが操作前フレームへ戻り、新しい操作が古い配置状態を引き継がない
- 連動先の確定中にSpace変更、機能停止、画面構成変更を行った場合、一部だけ変更された連動先が残らない
- 2回目の補正後も画面外周へ固定できないウィンドウは、その共有辺の接続を維持しない
- 高速リサイズ対策後も、スナップしていないウィンドウを固定対象として誤認しない
- 重いアプリを操作側にしても、ドラッグ中にAccessibilityの位置・サイズ照会が連続実行されない
- 60Hzと120HzのディスプレイでCPU使用率が操作終了後に通常値へ戻り、追跡処理やパネルが残らない
- 連動リサイズをオフにすると仮想ボックスと連動配置が発生せず、通常スナップとタイトルバードラッグは変化しない
- 連動リサイズを再度オンにすると、次の共有辺操作から追従が復帰する

## サイズ制約と離脱

- Discordまたはシステム設定を使い、最初から重なった二分割を作る
- 重なりを減らす方向では、操作中の辺が制約ウィンドウの実際の端へ着くまで仮想追従が始まらない
- 連動先が受け入れられない小さなずれではグループを維持する
- 重なり許容度を10%、50%、90%へ変え、新規再分割と既存辺の離脱しやすさが変化する
- 仮想領域が対象ウィンドウの許容侵害率を超えるとぼかしが消える
- 許容度より5ポイント安全側へ戻すとぼかしが再表示され、境界付近で点滅しない
- 許容侵害率を超えたままMouseUpすると、その共有辺だけが解除される
- そのまま画面端まで広げ、全画面方向の操作を妨げない

## 回帰確認

- 左右半分、上下半分、四隅、最大化
- 配置アシスト、背景クリック、Esc、30秒タイムアウト
- Undoとスナップ前サイズへの復元
- 同一アプリの複数ウィンドウとタブ分離
- Space切り替え、スリープ復帰、画面構成変更
- 異なる拡大率の複数ディスプレイ間移動
- 候補画像OFFとON
- グローバルショートカットの個別登録・個別消去・一括消去

## 公式ビルドの来歴確認

- 未コミットまたは未追跡ファイルがある状態で`./Scripts/build-official.sh`が失敗する
- Git管理外のコピーから`./Scripts/build-official.sh`が失敗する
- Community版を未コミット状態で作成した場合、`SnapFlowSourceDirty`が`true`になる
- コミット済みのクリーンなタグから作成した公式版で、`SnapFlowSourceDirty`が`false`、`SnapFlowSourceRevision`がタグ対象コミットと一致する

## コミットとPull Request

全確認後に、変更ファイルだけをステージして差分を再確認します。

```zsh
git add VERSION BUILD_NUMBER CHANGELOG.md README.md Sources Tests Documentation
git status --short
git diff --cached --check
git diff --cached --stat
git diff --cached
git commit -S -m "Add dynamic split resizing"
git push -u origin feature/dynamic-split-resize
```

Pull Requestでは、AccessibilityによるMouseUp後のリサイズ、画面収録を使わない仮想ボックス、設定保存形式へのキー追加、ウィンドウ固有の侵害率、一段階再分割、一括ロールバックと既知の制約を明記します。CI成功後に`main`へ統合し、Community版の実機確認が完了するまではv1.1.0タグを作成しません。
