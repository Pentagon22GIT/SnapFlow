# SnapFlow v1.2.0

## 共有境界につまみを追加

分割したウィンドウの境目へ、WindowsやiPadOSに近い操作感のリサイズつまみを追加しました。共有辺全体をつかめ、三分割では接している区間だけ、四分割では実際に高さや幅が一致した線全体が対象になります。高さが異なる左右の横線は独立して動かせます。交差点ではドラッグ方向から軸を決めます。つまみとガイドはマウスへ直接追従するため、YouTubeなど重いウィンドウの描画が遅れてもガイド自体は影響を受けにくくなります。

別のウィンドウやSnapFlowの設定画面が共有辺を覆っている場合、覆われた区間のつまみと入力判定を無効化します。参加ウィンドウはID、PID、現在フレームを照合し、一時的な座標差やIDの対応ずれでつまみが消え続けないよう改善しました。

## ドラッグ中の表示を選択可能

- 軽量: すべてアイコンで表示
- 標準: 操作中のウィンドウだけ内容を表示
- すべて表示: すべてのウィンドウ内容を表示

初期設定は「標準」です。アイコン表示の対象は操作終了まで実際にはリサイズしません。新しい画面キャプチャや権限は使用しません。

## 負荷と安全性の改善

ドラッグ中の実リサイズは古い要求を溜めず、常に最新の目標へ更新します。操作終了後の最終補正とキャンセルでも表示モードを維持し、新しいブラーを追加しません。全対象の位置とサイズを確認し、失敗した場合は操作前の状態へ戻します。

共有境界を直接動かしたとき、同じドラッグ中に許容範囲へ戻せば連動を続けられる設定も追加しました。意図した離脱を妨げないよう初期状態では無効です。スナップ成功時は共有境界でつながったグループを前面へまとめ、今回操作したウィンドウを最前面へ戻します。

## 接続グループの前面化を安定化

「スナップ中のウィンドウクリックによる最前面移動」を追加しました。初期設定はONです。スナップ中のウィンドウをクリックすると、現在も共有境界で接続されているウィンドウだけを一緒に前面へ移動し、クリックしたウィンドウをグループ内の最前面に保ちます。すでにグループ全体が前面にある場合は何も行わず、OFFの場合は通常のクリック動作を変更しません。

通常クリックと補助選択のキャンセル処理を分離し、クリックだけで進行中のスナップ確定や連動リサイズ確定を中断しないよう修正しました。クリック時のウィンドウ一覧は一度だけ取得して判定へ共有し、位置・長さ・表示状態が変化していないつまみは再配置しません。

別ウィンドウとの一時的な重なりや一瞬のZ順変化は、共有境界の恒久的な接続解除として扱いません。覆われた区間は表示と入力だけを一時的に無効化し、ウィンドウを離した後は現在の接続状態から安全に再計算します。

## 設定画面を整理

復帰設定は「スナップがタブの最小サイズを侵害した時にスナップを保持する」、割合設定は「スナップ保持の許容率」として役割を分けました。表示モードと復帰設定は連動リサイズの配下へ字下げし、親がOFFの間は無効表示します。許容率は新しいスナップにも使うため、独立した「最小サイズの判定」へ配置しました。また、設定画面を初めて開いたときに最下部が表示される場合がある問題を修正しました。
